# Состояния навыка и повторение

> Состояние на 27.10.2026: Автомат четырёх статусов реализован как предварительная политика по 27 укрупнённым группам, а не по детальному каталогу навыков. Числовые пороги не валидированы; см. ../current-learning.md. Самооценка и мелкие навыки остаются целевой моделью.

## Разделение состояния и расписания

**LRN-01 · Согласовано.** Системное заключение и самооценка ученика независимы. Ученик может выбрать тему, попросить практику или пропустить рекомендацию, не переписывая историю.

**LRN-02 · Предлагается.** Внутреннее `practiceState` имеет три значения: not_started, practicing, demonstrated. Расписание задаётся отдельно: lastQualifiedSuccessAt и nextReviewAt. Четыре видимых статуса — представление этой модели:

| Условие (проверяется сверху вниз) | Видимый статус | Смысл |
|---|---|---|
| practiceState=not_started | Не пробовал | Нет практических попыток по проверенному материалу навыка |
| practiceState=practicing | Практикую | Есть практика; свидетельств устойчивого результата недостаточно |
| practiceState=demonstrated и now >= nextReviewAt | Пора повторить | Получалось; подошёл срок закрепления |
| practiceState=demonstrated, срок не наступил | Получается | Есть достаточно самостоятельных результатов |

«Пора повторить» не означает утрату знания и не уменьшает накопленный прогресс. Нехватка данных о сроке не трактуется как просрочка: она отражается как ошибка конфигурации/«срок не рассчитан».

**LRN-03 · Согласовано.** Один правильный ответ не даёт «получается». Нужны разные примеры и повторная проверка после перерыва. Конкретные числа — предмет педагогического ревью и пилота.

**LRN-04 · Предлагается.** Практическая попытка по навыку допустима для охвата и practicing при проверенных условии, эталоне и диагностическом соответствии. Помощь не мешает учитывать сам факт практики. Свидетельство для окна оценки дополнительно требует одновременно:

- проверенных условия, эталона и диагностического соответствия целевому навыку;
- действующей версии материала и политики;
- валидной самостоятельной первой попытки до помощи и обратной связи — как для успеха, так и для ошибки;
- принадлежности выбранной версии модуля; отозванные оценки не участвуют.

Попытки по непроверенному материалу видны в общей истории, но не дают вывода о навыке. Открытие правила без попытки не переводит not_started в practicing; интерфейс отдельно показывает «правило прочитано».

## Предлагаемый воспроизводимый кандидат v0

**LRN-05 · Предлагается, НЕ утверждено для обучения.** Числовой профиль [reference-profile.json](reference-profile.json) позволяет разработать и проверить алгоритм до педагогического согласования. Пример не является доказательством эффективности.

Алгоритм для одного навыка, заданного now (UTC):

1. Удалить дубликаты по eventId, применить отзывы/исправления; не учитывать события будущего относительно now. Отсортировать по submittedAt, затем eventId. Последовательно обработать историю; шаги 2–6 применяются к каждому её префиксу. Отдельно учитывать факт практики, а для окна — только самостоятельные свидетельства по LRN-04.
2. Для каждой cardId оставить последнее квалифицируемое свидетельство. Взять последние `evidenceWindowDistinctCards` таких записей.
3. При отсутствии допустимой практики → not_started. Если практика есть (даже только с помощью), но успех ещё не подтверждался → practicing. Пустое самостоятельное окно при практике с помощью не считается отсутствием знакомства.
4. Успех: все записи полного окна correct, как минимум `minimumSessions` различных сессий; между первой и последней успешной записью окна не менее `minimumSpanHours`. Разные сессии сами по себе не заменяют временной интервал.
5. При успехе → demonstrated. nextReviewAt = время последнего успеха + `reviewAfterHours`. В v0 интервал фиксирован; увеличение интервалов — отдельная будущая политика.
6. Если навык уже был demonstrated, новый успех обновляет срок только при повторном выполнении условия полного окна. Новая изолированная ошибка не стирает статус. `demotionErrors` неправильных ответов на разных карточках в текущем окне переводят в practicing и предлагают диагностику. Остальные случаи сохраняют прежнее достижение и срок.
7. После отзыва свидетельств пересчитать хронологически по тем же шагам; исчезнувшее основание не сохранять как подтверждённое. Показать причину корректировки.

Для воспроизведения результата необходимы история с версиями, профиль алгоритма и now. Проекция — кэш, а не единственный источник истины. Много повторов одной карточки не закрывают окно разнообразия.

## Самооценка

**LRN-06 · Согласовано.** Отдельные значения: unclear («пока непонятно»), more_practice («нужна ещё практика»), confident («чувствую себя уверенно»); отсутствие записи не является уверенностью или неуверенностью. Запись включает skillId, время и ID события.

- confident при недостатке свидетельств → «Ты уверен в теме. Проверим на нескольких примерах?».
- more_practice при demonstrated → предложить закрепление, не понижая системную оценку.
- unclear → предложить правило/простую диагностику, не считать это ошибочным ответом.

**LRN-07 · Согласовано.** Объяснение статуса доступно по нажатию: использованные самостоятельные результаты, разнообразие, перерыв, помощь и причина повторения. Нельзя заменять основания непонятным процентом «ИИ уверен».

## Отсутствующий контент

Если по навыку недостаточно проверенных разных карточек, система показывает «Недостаточно проверенных материалов для оценки», а не заставляет ученика повторять один ID ради статуса. «Не пробовал» в отсутствие практики допустим, но рядом видна недоступность оценки. Это статус готовности материалов, не пятое состояние знания.
