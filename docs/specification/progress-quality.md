# Прогресс, полнота и наглядный дашборд

> Состояние на 27.10.2026: На #progress работает реальный расчёт по предварительной политике: охват карточек / 2140, закрепление укрупнённых групп / 27. Демонстрационный экран удалён; целевой детальный каталог навыков и редакторский дашборд ещё не реализованы.

Текущая числовая модель и её отличие от целевой модели мелких навыков:
[формулы, настройки, знаменатели](../current-learning.md). После согласования
автора оценки обновляются по завершению (1/n либо 0), а карточка и группа
имеют независимые статусы; ранние требования разнообразия ниже — история предложения.

## Три независимых измерения

**PRG-01 · Согласовано.** Не смешивать количество действий, подтверждённый результат и готовность банка. Ручное «изучено», просмотр карточки, совпадение с непроверенным ответом и редакторская проверка — разные факты.

**PRG-02 · Предлагается по последнему обсуждению.** Основной обзор строится по крупным темам: орфография, пунктуация, нормы языка, работа с текстом. Это верхнеуровневая навигация, не четыре одинаковых по трудности блока. Внутри — конкретные навыки. Окончательный состав тем и принадлежность навыков проходят педагогическое ревью.

### Охват: насколько широко попробовал

Для версии учебного модуля M:

- S — множество уникальных обязательных skillId модуля.
- P — навыки S с хотя бы одной квалифицируемой практической попыткой по проверенному материалу. Попытка с помощью тоже считается знакомством, но не подтверждением результата.
- `coverage = |P| / |S| × 100%`.

Прочитанное правило отдельно показывается как просмотр, не увеличивает P. Десятки повторов одного навыка не расширяют охват. Практика непроверенных карточек остаётся в истории действий, но не меняет учебный охват.

### Закрепление: по скольким навыкам получается

- D — навыки S с practiceState=demonstrated.
- `consolidation = |D| / |S| × 100%`.

D включает навыки, которым пора повториться. Срок не стирает достижение; реальное изменение оснований/результатов может изменить состояние по LRN-05. Учитываются разные задачи и самостоятельные попытки, не просто число отмеченных карточек.

**PRG-03 · Предлагается.** В интерфейсе использовать понятное название «Закрепление» / «Получается по 9 из 24 навыков», а не неопределённый «процент изученного русского языка». В документации «глубина» означает здесь долю подтверждённых навыков. Это условная операционализация, а не измерение всех аспектов знания и не прогноз балла ЕГЭ.

### Дополнительный показатель устойчивости

Можно отдельно показать: «Из 9 закреплённых навыков 3 пора повторить». Не создавать третий крупный процент «актуальности» без доказанной пользы. Скорость, серии посещений и рейтинги не входят в mastery-процент.

## Знаменатель и округление

**PRG-04 · Предлагается.** Все обязательные навыки зафиксированного модуля остаются в S, в том числе временно недоступные по причине контента. Иначе удаление непроверенных материалов искусственно повышает результат. Рядом показывать «для N навыков ещё нет проверенных упражнений». Дополнительные необязательные навыки не меняют основной знаменатель.

**PRG-05 · Предлагается.** При пустом S показывать «маршрут ещё не настроен», не 0% и не 100%. При отсутствии размеченных навыков — «оценка навыков пока недоступна», не вычислять процент по количеству карточек.

**PRG-06 · Предлагается.** Для отображения округлять до целого стандартным round, но положительная незавершённая доля не отображается как 100%: `min(99, round(value))` при numerator < denominator. При ненулевом numerator и округлении в 0 показывать «менее 1%». Всегда сохранять точные «N из M»; расчёты выполняются до округления.

**PRG-07 · Предлагается.** Навык может участвовать в нескольких темах; общий итог считает уникальные skillId, а не сумму тематических процентов. Для примитивного первого интерфейса предпочтительна одна основная тема у навыка, остальные связи — дополнительные. Вес навыков по умолчанию одинаковый; взвешивание нельзя вводить скрыто.

## Экран без перегрузки

**PRG-08 · Предлагается.** Первый экран прогресса имеет три уровня:

1. **Главный итог:** «Получается по 9 из 24 навыков · 38%». Под ним: «Попробовали 17 из 24 · 71% охвата». Пояснение термина доступно по нажатию.
2. **Четыре строки крупных тем:** название, «получается N/M», одна горизонтальная сегментированная полоса, текст «пора повторить R». Без четырёх круговых диаграмм и разных шкал.
3. **По нажатию на тему:** список навыков с четырьмя статусами, основаниями и кнопкой подходящего действия. История попыток — ниже или в отдельном раскрываемом разделе.

Сегменты полосы, всегда в одном порядке:

- получается — спокойный зелёный;
- пора повторить — зелёная основа с штриховкой/значком часов, а не тревожный красный;
- практикую — синий/сиреневый;
- не пробовал — нейтральный серый.

Распределение исчерпывает S по видимому статусу. Цвет не единственный носитель: рядом числа/подписи; доступное описание содержит все четыре количества. Легенда одна на экран. Сегменты не обязаны быть кликабельными; вся строка темы — доступная кнопка/ссылка. На телефоне строки вертикальные, без горизонтальной прокрутки. Пока важны четыре состояния, диаграмма-паук и граф зависимостей не нужны.

**PRG-09 · Предлагается.** Не добавлять вторую диаграмму «глубины» рядом с полосой: глубина уже выражена подтверждённой частью. Охват — число и текст. Повторение — действие «Повторить 3 навыка», если есть пригодные задания. Ни один график не изображает ещё не подключённый алгоритм.

### Контрольный пример

В S=24 навыка: 6 «получается», 3 «пора повторить», 8 «практикую», 7 «не пробовал».

- Полоса: 6 + 3 + 8 + 7 = 24.
- Охват: (6+3+8)/24 = 70,833…% → 71%, 17 из 24.
- Закрепление: (6+3)/24 = 37,5% → 38%, 9 из 24.
- Завтра срок наступил ещё у двух навыков: 4 + 5 + 8 + 7. Закрепление остаётся 38%, меняется только приглашение к повторению.
- Добавлен новый навык в версии модуля: прежний результат 9/24 сохраняется для прежней версии; новый 9/25 показывается с пояснением обновления программы, не как ошибка ученика.

## Полнота и качество материалов

**QLT-01 · Согласовано.** Редакторский дашборд отделён от ученического. На нём:

- наличие ответов / карточки, где нужен эталон;
- проверенность ответов / тот же знаменатель;
- наличие и проверенность объяснений отдельно;
- покрытие диагностическими упражнениями по навыкам;
- полнота маршрута относительно заявленных целей;
- актуальность классификации относительно конкретного года ЕГЭ.

**QLT-02 · Предлагается.** Для каждой характеристики показывать числитель, знаменатель, исключения и версию. extended_text не считается «с отсутствующим коротким ответом»: для него требуется проверенная рубрика/критерии. Исключение из applicability требует явного основания, не автоматической догадки.

**QLT-03 · Согласовано.** Исследовательский модуль допускается к школьникам только после проверки условий, ответов/критериев, объяснений, разметки навыков и тестовых форм. Красивый интерфейс и наличие строк не являются достаточной готовностью. Остальной банк может оставаться демонстрационным с предупреждениями, вне исследования.

**QLT-04 · Предлагается.** Полнота маршрута: число целей с проверенными достаточными материалами / число заявленных целей версии модуля. Достаточность учитывает разнообразие, диагностику, повторение и отсутствие пересечения тренировочных заданий с исследовательским тестом; критерии достаточности утверждаются до выпуска.
