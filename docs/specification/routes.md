# Маршруты и экран этапа

> Состояние на 26.10.2026: Это спецификация будущего учебного маршрута, а не URL-навигации сайта. Сейчас ученик выбирает направление/карточку; кнопка следующей карточки идёт по текущей группе без диагностики предпосылок. Действующие URL описаны в architecture.md.

**RTE-01 · Согласовано.** Маршрут предлагает система/редактор, ученик не обязан рисовать граф или перетаскивать учебные блоки. Основные входы: «Продолжить маршрут», «Выбрать тему», «Повторить».

**RTE-02 · Согласовано.** Видимый маршрут — небольшая вертикальная дорожка выбранного направления, не весь граф языка. На компьютере допускаются ответвления. На телефоне не требуется перетаскивание или точное попадание в узлы графа.

Нажатие на этап открывает:

1. Название и конкретную цель: что ученик сможет делать.
2. Системный статус, основание и отдельную самооценку.
3. Связанные проверенные правила (либо честное отсутствие).
4. Упражнения: основы, применение, смешанная практика; доступность эталона видна до начала.
5. Действия «Начать/продолжить», «Нужна ещё практика», «Выбрать другое».

**RTE-03 · Предлагается.** Route имеет ID, version, moduleVersion и этапы; Stage — ID, skills, prerequisiteStageIds, ruleIds, practicePools. Граф предпосылок ацикличен, ссылки существуют; цикл блокирует выпуск маршрута, а не весь банк.

**RTE-04 · Согласовано.** Предпосылки — рекомендации, а не жёсткие блокировки. Причина перехода объясняется. Невыполненная основа предлагает диагностику; ученик может продолжить выбранную тему. Нельзя выводить доказанный пробел из одной ошибки комплексного задания.

## Состояние этапа

**RTE-05 · Предлагается.** Этап не является одной карточкой. Целевые навыки этапа фиксированы версией модуля. «Получается» — когда все целевые навыки demonstrated; «пора повторить» — если при этом хотя бы один срок наступил. «Не пробовал» — если все not_started; остальные сочетания — «практикую». По нажатию всегда видна раскладка по навыкам. При недоступности оценки показывается отдельное предупреждение о материалах.

## Предложение следующего шага v0

**RTE-06 · Предлагается.** До экспериментального адаптивного алгоритма используется прозрачный детерминированный порядок:

1. Явный выбор ученика имеет приоритет; предложение не перенаправляет его молча.
2. В режиме «Продолжить маршрут»: незавершённый выбранный этап, если доступен; иначе первый этап по редакторскому order с недостигнутой целью. Из его незакреплённых предпосылок предложить самую раннюю, но разрешить отказаться.
3. В режиме «Повторить»: только demonstrated-навыки с наступившим сроком, сначала самый ранний nextReviewAt. При равенстве — order, затем skillId.
4. Для выбранного навыка: только карточки действующего проверенного practicePool; сначала не встречавшиеся в текущей сессии, затем дольше всего не использовавшиеся, при равенстве cardId.
5. Порог повторов одной темы из профиля не превышается автоматической выдачей: предложить смену/перерыв. Самостоятельный выбор темы не запрещён. Если альтернатив нет, не зацикливать выдачу, объяснить ситуацию.
6. Если проверенного задания нет, сообщить об ограничении; не подменять его непроверенным и не считать навык завершённым.

Алгоритм не утверждает, что редакторский порядок сам по себе оптимален. Он даёт воспроизводимую базовую линию для сравнения будущей адаптации.

## Пример направления, не утверждённая программа

Грамматические основы → простое/сложное предложение → связь частей → пунктуация → смешанная практика. Отдельные ветви: однородные члены, обособление, вводные конструкции. Список навыков и предпосылок проверяет учитель. В банке ФИПИ может не хватать упражнений на отдельную основу; они добавляются как самостоятельные авторские материалы с review.
