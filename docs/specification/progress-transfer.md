# Локальный перенос прогресса, формат v1

Статус: **реализовано**, 26.10.2026. Пользователь выбирает файл и подтверждает объединение. Это ручной перенос между браузерами/устройствами, без аккаунта, сети и автоматического разрешения конфликтов синхронизации.

## Пользовательский сценарий

1. В заголовке «Мой прогресс» нажать «Скачать прогресс».
2. Сохранить JSON; перенести его на другое устройство любым выбранным способом.
3. Там открыть сайт, нажать «Загрузить прогресс» и выбрать файл.
4. Прочитать предварительный просмотр: новые попытки, добавляемые отметки, дубликаты, конфликты и неизвестные банку ID.
5. При желании скачать текущую копию; нажать «Объединить прогресс» или «Отмена».
6. Файл прочитывается в браузере и не отправляется приложением на сервер. Демо-проценты/статусы не экспортируются и не импортируются.

## Формат

Один объект: schemaVersion=1, exportedAt, events, lastCard (ID или null), tags. Файл не более 10 МБ; до 50 000 событий и 10 000 записей меток. Неподдерживаемые версии, лишние поля, некорректные типы, повторные ID внутри входного файла и повреждённый JSON отклоняются до записи.

Событие: непустой id длиной до 128 символов, cardId (6 заглавных hex-символов), time (распознаваемая дата), correct/assisted (boolean), materialVersion (положительное целое). Метки: fav, hard, studied, solved с boolean-значениями. solved сохраняется для совместимости, не становится новым подтверждением навыка.

Это формат нынешней истории интерфейса, а не целевой журнал всех будущих учебных событий. При развитии схемы понадобится новая версия и явная миграция. Файл не удостоверяет достоверность результатов: его владелец может редактировать JSON. Для исследовательского сбора данных нужен отдельный проверяемый контур.

## Объединение

- Уникальные события объединяются по id, сортируются по времени, затем id. Повторный импорт того же файла не удваивает историю.
- Если id совпал, а данные различаются, сохраняется локальное событие; конфликт показывается до подтверждения.
- Отметки объединяются через логическое ИЛИ. Импорт не снимает существующие отметки. Это сознательная политика восстановления резервной копии, не применение последних изменений аккаунта.
- Последняя карточка этого устройства сохраняется; значение из файла используется, только если локального нет.
- Валидные ID, которых нет в нынешнем каталоге, сохраняются с предупреждением. Реальные показатели банка учитывают только известные карточки.
- История не очищается, функции «заменить всё» сейчас нет. Отмена диалога не изменяет хранилище.

## Сохранение и ограничения

До записи сохраняются прежние значения затрагиваемых ключей в памяти. Если запись прерывается, новые ключи удаляются, прежние значения восстанавливаются; состояние приложения меняется только после успешной записи. При ошибке интерфейс показывает отказ. Если сам браузер препятствует восстановлению, это сообщается отдельно и предлагается сохранить копию из ещё открытой вкладки.

localStorage не транзакционная база: аварийное закрытие процесса между записями и одновременные изменения из других вкладок не покрываются гарантией атомарности. Импорт лучше выполнять в одной вкладке. Резервный файл рекомендуется сохранить до объединения. Автоматического резервного файла на сервере нет.

Тест `tests/progress_transfer_smoke.py` проверяет выбор файла, отмену, объединение/дубликаты/конфликты, сохранение меток, некорректный формат, восстановление после смоделированной ошибки квоты, экспорт и перезагрузку.
