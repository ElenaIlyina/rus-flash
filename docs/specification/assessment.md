# Ответы, попытки и оценивание

> Состояние на 27.10.2026: Работают выбор вариантов, упорядоченный ввод соответствий и краткий ответ. Помощь/повторная отправка сохраняются в локальном назначении после перезагрузки. Полного многоустройственного assignment-контракта нет; см. ../current-learning.md.

**ASM-01 · Согласовано.** Тип ответа определяет взаимодействие. Политика оценивания задаётся отдельно. Битмаска — формат ФИПИ-адаптера, а не универсальный тип ответа.

| Тип | Значение ответа | Базовая политика, предлагается |
|---|---|---|
| single_choice | ID варианта | Точное совпадение ID |
| multiple_choice | Набор ID | Совпадение множеств без повторов, порядок неважен |
| short_text | Строка | Совпадение с одним из acceptedAnswers после явно заданной нормализации |
| matching | Пары ID левой/правой стороны | Совпадение отображений; уникальность правых элементов определяется условием |
| ordered_sequence | Список ID | Точное совпадение с учётом порядка |
| extended_text | Развёрнутый текст | По критериям; без ложной строковой автопроверки |

Сопоставление с официальными баллами ЕГЭ отдельно версионируется по году. Частичное оценивание отдельных элементов ответа ЕГЭ пока не утверждено; результат 1/n оценивает число отправок, а не долю верно выбранных элементов. Если политика отсутствует, автопроверка недоступна; разработчик не угадывает её по формулировке.

**ASM-02 · Согласовано.** Показ ответа/подсказки и исправление после обратной связи отличаются от самостоятельного решения. Открытие справочного правила тоже фиксируется, но считать ли его подсказкой в конкретном режиме — явная настройка режима.

**ASM-03 · Предлагается.** Попытка содержит `eventId`, `learnerId` (локальный псевдоним), `cardId`, `cardRevision`, `assignmentId`, `sessionId`, `submittedAt`, `response`, `gradingPolicyVersion`, `result`, `assistance`, `evidenceEligibility`. Все ссылки версионированы. Значения response остаются локальными, пока нет отдельного согласованного режима передачи.

- result: correct, incorrect, ungraded; объяснение результата и версия эталона обязательны для оценки.
- assistance: answerRevealed, hintUsed, ruleOpened, feedbackAlreadySeen; это отдельные признаки, не один нерасшифрованный boolean.
- Пустой ответ не создаёт попытку, отображается просьба заполнить поле.
- Новое нажатие с тем же submission/event ID не создаёт второе событие. Новая реальная отправка создаёт отдельное событие.

**ASM-04 · Предлагается.** В пределах одного assignment самостоятельной считается только первая отправка до ответа/подсказки/обратной связи. Перезагрузка не сбрасывает сведения о показанной помощи. Новое назначение карточки после перерыва имеет новый assignmentId; повторение того же ID всё равно не заменяет требование разнообразия карточек.

**ASM-05 · Согласовано.** Нормализация явная: trim, регистр, пробелы, е/ё и порядок — отдельные параметры. Ни одна «удобная» нормализация не применяется ко всем типам автоматически. Например, порядок важен в соответствиях, но не в множественном выборе.

**ASM-06 · Согласовано.** Непроверенный эталон позволяет только демонстрационную сверку с предупреждением. Отсутствующий эталон — ungraded/самопроверка. Ни такой результат, ни ручное «изучено» не подтверждают освоение навыка.

**ASM-07 · Предлагается.** При отзыве ошибочного эталона история не удаляется. Отдельная запись об отзыве исключает соответствующее свидетельство; пересчёт выполняется с объяснением «материал исправлен». Автоматическое переоценивание возможно только с записанной исходной response и явной новой версией политики; исходная оценка сохраняется.

## Примеры

1. multiple_choice, correct=[a,c], response=[c,a] → correct при exact_set.
2. matching, correct={A:3,B:1}, response={A:1,B:3} → incorrect, несмотря на одинаковый набор цифр.
3. Краткий ответ с acceptedAnswers=[«народный»], trim=true, caseInsensitive=true: « НАРОДНЫЙ » → correct.
4. Тот же ответ после кнопки «Показать ответ» → correct, assisted; не свидетельствует о самостоятельном успехе.
5. Без эталона нажатие «изучено» меняет только пользовательскую отметку.

## Фактическая версия интерфейса — 27.10.2026

Выбор вариантов и явные наборы позиций сравниваются без учёта порядка;
соответствия и строки номеров предложений сохраняют порядок. Проверка отдельно
от DOM — assessment.js. Материалы с выявленным блокирующим дефектом не оцениваются.

После последующего согласования автора правило не маркирует помощь.
Подсказка/ответ/разбор маркируют assisted, а повторная отправка сама по себе — нет.
Счётчик n и помощь сохраняются после перезагрузки. Одно завершение обновляет
оценку один раз: r=1/n без помощи или 0 с помощью. Новое назначение может
начаться сразу — в том числе после просмотра ответа; система доверяет ученику.
Прежнее ASM-04 про обязательный перерыв — история предложения, не действующее правило.
ASM-02 уточнено: в текущем учебном режиме правило не снижает результат.

Пустой ответ не создаёт события; незавершённая ошибка сохраняется в истории,
но не меняет оценку. [Точные формулы, статусы и настройки](../current-learning.md),
[перенос событий v2](progress-transfer.md).
