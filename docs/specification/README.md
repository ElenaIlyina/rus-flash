# Спецификация «Слово за слово»

Версия: **0.1-draft**, 25 октября 2026. Это начало спецификации продукта, а не заявление о полной специфицированности или готовности реализации.

Цель: разработчик, не читавший переписку, должен восстановить согласованное поведение, различить проект и существующий код, реализовать его и проверить по примерам. План развития отвечает «зачем и в какой очередности», спецификация — «какие данные, правила и наблюдаемые результаты».

## Статусы требований

- **Согласовано** — принцип обсуждён с владельцем продукта; это целевое требование, не утверждение о наличии кода.
- **Предлагается** — конкретизация для ревью; не внедрять как утверждённое правило без согласования.
- **Реализовано** — наблюдается в текущей ветке; приведены файлы и проверки.
- **Открыто** — решения недостаточно для однозначной реализации.

Если раздел содержит смешанные статусы, они указаны у требований. Требование без статуса считается предложением. Поведение, которое пока нельзя однозначно восстановить, явно вынесено в открытые вопросы. Оно не должно незаметно определяться разработчиком или моделью.

## Как сопровождать

**DOC-01 · Согласовано.** Спецификация хранится в Git вместе с программой. Существенное изменение поведения включает изменение соответствующего требования, примера и сценария приёмки в одном наборе изменений.

**DOC-02 · Предлагается.** Требования имеют постоянные ID: DOM, ASM, LRN, RTE, PRG, QLT, ARC. ID не переиспользуются. В описании будущего PR перечисляются затронутые ID, изменения формата/миграции и способ проверки.

**DOC-03 · Предлагается.** При изменении смысла ответа, навыка, оценивания или знаменателя повышается соответствующая версия. Дизайн не меняет учебную семантику. Старые результаты не переписываются молча.

**DOC-04 · Предлагается.** На каждый реализованный инвариант нужен автоматический тест там, где он проверяет реальное поведение; предметная корректность дополнительно проверяется редактором/учителем. Текстовые сценарии сейчас не выдаются за исполненные тесты.

## Границы версии 0.1

Описаны прежде всего обучение, качество контента и маршруты. Точный HTTP API будущего сервера, авторизация, конфликтные изменения между устройствами, финальная схема всех сущностей и педагогические пороги ещё не утверждены. Поэтому восстановить **всю будущую программу** по этой редакции пока нельзя. Эти пробелы перечислены в decisions.md; спецификация будет наращиваться параллельно реализации.
