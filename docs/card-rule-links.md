# Связи «карточка — правило — параграф»

27.10.2026. Текущее состояние и целевой контракт разграничены ниже.

## Принцип

```text
карточка + версия
    → проверяемое умение / часть задания
    → устойчивый ruleId
    → sourceRef: конкретное издание, параграф, страница, URL
```

Это связи «многие ко многим», а не один номер ЕГЭ → один параграф. КЭС и позиция
служат для предварительного поиска, но не заменяют содержательного сопоставления.
Нормативный текст и наше понятное объяснение также не являются одной сущностью.

## Пример 09169B

| Часть карточки | Что проверяется | Локальное правило |
|---|---|---|
| Ряд 2 | З/С в приставках | prefixes-z-s |
| Ряд 3 | ПРЕ-/ПРИ- | pre-pri |
| Ряд 4 | И/Ы после приставки | prefixes-i-y |
| Ряд 5 | Разделительные Ъ/Ь | separating-signs |

Это пример содержательной разметки по прочитанному условию. Первый ряд требует
дополнительного разбора написаний и не покрывается автоматически всеми четырьмя
параграфами. Неверный ответ на карточку в целом не доказывает ошибку в каждом
из этих правил. Для адресной диагностики понадобится ответ по частям или отдельное
атомарное упражнение; из одного итогового набора цифр нельзя вывести все причины.

## Что уже реализовано

В data/knowledge/handbook.json четыре локальных параграфа с постоянными id.
Генератор прикрепляет их к карточкам группы 10; связи пока укрупнённые, без
привязки к каждому ряду. Это временная реализация, а не завершённая разметка банка.

Веб-ссылка #knowledge?rule=prefixes-i-y&card=09169B открывает правило, сохраняет
контекст возврата и учитывается как помощь при открытии из упражнения. Локальный
номер §2 — номер нашего черновика, а не номер параграфа Лопатина.

## Целевые записи — ещё не текущая схема исходных карточек

```json
{
  "cardId": "09169B",
  "materialVersion": "версия материала",
  "links": [
    {
      "partId": "row-4",
      "skillId": "prefixes.i-y",
      "ruleId": "prefixes-i-y",
      "relation": "tested",
      "reviewStatus": "draft"
    }
  ]
}
```

partId относится к конкретной версии карточки: перестановка рядов требует
сверки связей. relation различает tested (непосредственно проверяется),
prerequisite (необходимая основа), help (материал для объяснения).

У правила отдельно хранятся источники:

```json
{
  "ruleId": "prefixes-i-y",
  "sourceRefs": [
    {
      "editionId": "lopatin-2020",
      "paragraph": null,
      "printedPage": null,
      "url": null,
      "status": "awaiting_source_text"
    }
  ]
}
```

null здесь намеренный: издание найдено в библиографии ФИПИ, но текст пока
не получен. Номер и страницу нельзя угадывать или брать из другой редакции.
Библиографическая запись издания должна содержать авторов/редактора, название,
издательство, год, при наличии ISBN, URL получения, SHA-256 сохранённой копии.
При смене издания создаётся новый editionId; прежние ссылки не перенумеровываются.

## Порядок заполнения

1. Получить и проверить титульный лист и полноту источника.
2. Выделить разделы/параграфы с исходной нумерацией и страницами.
3. Связать устойчивые ruleId с конкретными sourceRef, сохранив локальные ссылки.
4. Разметить проверяемые действия и части карточки; при необходимости несколько правил.
5. Провести предметное ревью связи, примеров и объяснения.
6. Только по достаточной диагностике использовать результат для мелких skillId.

Для первой партии связи можно заполнять вручную. Позднее поиск/RAG может
предлагать кандидатов, но не подменяет подтверждение источника и предметное ревью.
[Выбор справочника](knowledge-sources.md), [текущая реализация](knowledge-and-order.md).

## Реализация после получения книги

Получено издание 2007, а не 2020. sourceRefs первых четырёх правил заполнены
для editionId=lopatin-2007, part=orthography с реальными номерами параграфов.
Веб-ссылка включает sourceId, например lopatin-2007-orthography-12.
У издания 2007 самостоятельная нумерация внутри двух разделов; голого номера
§12 недостаточно. Поле страницы остаётся null (FB2). Пример sourceRefs с null
для lopatin-2020 выше остаётся описанием ещё не полученного издания.
[Подробности и структурная проверка](handbook-import.md).

Для первых 12 карточек группы 10 уже заполнены **источники объяснений по рядам**
в prefix_card_reviews.json. Например, ряд 4 карточки 09169B ведёт в орфографию
§12 издания 2007. Это точнее временной групповой привязки и доступно в разборе.
Детальные skillId и диагностическое разложение ошибки по частям пока не добавлены:
ссылка на правило не равна автоматическому заключению о причине ошибки.
