# Информация по парсингу и проверке заданий ФИПИ (ege.fipi.ru)

Исторические наблюдения. Прежние номера в этом документе могут отличаться
от [позиций проекта ЕГЭ-2027](docs/ege-2027-card-mapping.md). Сохранённые
ответы не означают предметную проверку объяснений.

## 1. Где брать карточки и список заданий
- **Эндпоинт банка:** `https://ege.fipi.ru/bank/questions.php`
  - Параметры: `proj` (ID проекта, см. ниже), `page`, `pagesize`.
  - Отдаёт HTML со всеми карточками страницы (не JSON): каждая карточка содержит `guid` (в `<input name="guid">`), условие, КЭС, тип ответа, варианты.
  - FIPI лимитирует общий вывод ~2200 карт, поэтому скрейпер тянет всё за один запрос: `page=1&pagesize=3000` (это текущее поведение `scripts/parse_fipi_missing.py`).
- **Идентификатор проекта:** `AF0ED3F2557F8FFC4C06F80B6803FD26` (все карточки банка висят под ним).
- Все 6-значные номера заданий сохранены в файле `data/fipi_numbers.txt` (всего 2140 номеров) — вход скрейпера.

## 2. Структура данных задания
Со страницы каждого задания можно извлечь:
- **Номер** (например, `41634D` / `8E0C44`).
- **GUID** (внутренний идентификатор в атрибутах `changeFavour` или `<input name="guid">`).
- **Текст условия** (`<div class="qblock"> ... <TR><TD ... class='cell_0'>`).
- **Тепмы / КЭС** (`<td class="param-name">КЭС:</td><td class="param-row">...</td>`).
- **Тип ответа** (`<td class="param-name">Тип ответа:</td>`).
- **Варианты ответа** (извлекаются из таблицы дистракторов).

## 3. Проверка правильных ответов (API solve.php)
Сервер ФИПИ проверяет ответы динамически через POST-запрос:
- **URL:** `https://ege.fipi.ru/bank/solve.php`
- **Метод:** `POST`
- **Обязательные заголовки:** Куки сессии (полученные при GET-запросе к странице банка), `X-Requested-With: XMLHttpRequest`, `Referer` (страница банка), `User-Agent`.
- **Сессия:** сначала GET `questions.php` через тот же opener, чтобы получить/сохранить cookies, затем POST `solve.php`.
- **Тело запроса (form-urlencoded):**
  - `guid`: GUID конкретного вопроса
  - `answer`: битовая строка выбора вариантов (например, `01100` для 2-го и 3-го вариантов)
  - `ajax`: `1`
  - `proj`: ID проекта (`AF0ED3F2557F8FFC4C06F80B6803FD26`)
- **Ответ сервера:**
  - `'3'` — ответ верный
  - `'2'` — ответ неверный
  - `'0'` — ошибка / не решено

## 4. Формат answer для choice-заданий: сокращение vs битмаск

Для заданий с выбором ответов solve.php принимает **как перечисление номеров, так и битмаск**:
- `'245'` (перечисление, 1-based) и `'01011'` (битмаск) — эквивалентны, оба дают `'3'`.
- Проверено на задании 1 (билет 1, скрипт `scripts/verify_answers_fipi.py`): ответ-строка в
  `answer_verify` хранится как **перечисление цифр** (`'134'`, `'245'`, `'2345'`), и если слать
  её «как есть», без конвертации — сервер возвращает `'3'`. Разделителей (запятых/пробелов) быть не должно.
- Порядок цифр в перечислении не важен (сортируется сервером), в битмаске важна позиция.
- УСТАРЕЛО, см. раздел 5: для мультивыборных вопросов конвертация в битмаск обязательна.

## 5. Тонкость (проверено на задании 2): одиночная цифра ≠ перечень

Для заданий с **мультивыбором** (5 вариантов, «Укажите номера ответов») solve.php принимает
только **битмаск** из 5 позиций: `'125'` не работает (сервер читает его как `'1'` и возвращает
`'2'`), а `'11001'` даёт `'3'`. Тест на 011D96: enum `'1'` → `'2'` (неверно), mask `'11001'` → `'3'`.

В задании 1 (там тоже «укажите номера») enum почему-то проходил — вероятно, у тех вопросов
 однозначные комбинации совпали с битмасками либо сервер держит другой парсер для этого проекта.
**Правило надёжное: для любых choice-заданий слать только битмаск длиной = числу вариантов**

| Тип задания | формат answer/answer_verify в data/ | формат для solve.php |
|---|---|---|
| choice, «укажите номера» | перечень цифр (`'245'`) | битмаск (`'01011'`, длина = числу вариантов) |
| краткий ответ (слово/номер предл.) | само слово/число | как есть (`'наоборот'`, `'18'`) |

## 6. Задание 8 (соответствие): answer — строка перестановки

Формат: «к каждой позиции первого столбца подберите…» (5 ошибок ↔ 7–9 предложений).
- `answer` в data/ — **последовательность номеров предложений** по позициям 1–5 (напр. `'13254'`).
- Порядок **важен** (это перестановка, а не множество: `'13254'` OK, `'52341'` → `'2'`).
- solve.php принимает строку «как есть», битмаск не нужен; проверено: 71/71 → `'3'`.

## 7. Словарная статья (т3 «определите значение... выпишите цифру»): ответ = битмаск

Вопросы с чекбоксами значений словарной статьи (4–6 вариантов, form submit собирает
`test0..testN.checked` в строку '1'/'0') — ответ **только битмаском длиной = числу значений**:
- `'1'` при 4 значениях → `'1000'` (06A9D8: enum '1' → '2', mask '1000' → '3').
- `'2'` при 5 значениях → `'01000'` (0714FC).
Проверено: все 48 таких карт т3 → `'3'`. Общее правило прежнее: choice = битмаск,
длина = числу вариантов в конкретной карте.
