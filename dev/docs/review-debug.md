# Ревью карточек

С 29.10.2026 инструмент находится отдельно в `dev/review/`.
В ученическом приложении нет отладочного режима, кнопок или загрузки реестров.

## Открытие

Из корня полного Git-клона:

```bash
python3 dev/scripts/build_review_data.py
python3 -m http.server 8000 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8000/dev/review/`.
Слева — очередь и фильтры, справа — замечания и настоящее приложение в iframe.
Переходы между карточками в приложении обновляют панель замечаний.

В очереди остаются фильтры «На ревью», «Есть замечания», «Приняты», «Все».
Карточки с `authorReviewRequired=false` не требуют приёмки очередного старого
объяснения и не подставляются в очередь без дополнительных замечаний.
Это не автоматический diff всей ветки.

## Принятие и сохранение

«Разбор принят» сохраняет хеш версии под прежним ключом
`slovo_review_acceptances_v1`. «Вернуть на ревью» снимает отметку.
Версия учитывает карточку, пояснение, подсказку, правила, источники и замечания.
При переносе сохранены все 31 запись и их версии: прежние локальные отметки
на том же origin продолжают подходить. Новый материал может менять версию.

Отметка не закрывает замечания, не даёт разрешения менять условие и не является
предметной приёмкой учителем. Нажатие не добавляет учебных событий и не меняет
оценки. Файл `review-data.json` генерируется только для разработки и не хранится
в Git. Принятие локальное; решения, которые должны попасть в Git, фиксируются
в диалоге и редакторских файлах.

Материалы ревью: `dev/data/knowledge/*_card_reviews.json`,
`dev/data/knowledge/review_issues.json`, [журнал](correction-log.md).
Сборка приложения читает уже подготовленные `data/knowledge/card_support.json`,
а не эти реестры. После содержательных правок сначала выполните
`python3 dev/scripts/publish_content.py`.
