# Проверка кандидатов ответа на компьютере автора

Скрипт: [check_fipi_answers.py](../scripts/check_fipi_answers.py).
Требуется только **Python 3**, дополнительных пакетов нет. Запуск из копии
проекта; адрес сервера и сессия уже настроены. Карточки приложения не меняются.

## Один файл рядом с исходным скриптом

Для переданного образца достаточно скопировать один `check_fipi_answers.py`
в папку `src/`, рядом с `fetch_fipi_cards.py`. Репозиторий и отдельный план
не требуются. В скрипт встроены 935 имеющихся ответов; для образца 005141
добавлена гипотеза. В полном `src/cards` будут проверены все доступные кандидаты.
Из папки, содержащей `src`, выполнить:

```bash
python3 src/check_fipi_answers.py
```

Скрипт найдёт каталог `src/cards` и предложит «неизбежность» для 005141.
Это гипотеза, пока сервер не ответил 3. Вне репозитория результат сохраняется
в `fipi-results/`; полный путь печатается в конце. Прислать можно архив
с `src/cards/` и `fipi-results/`.

Для одного другого JSON можно явно передать кандидаты:

```bash
python3 src/check_fipi_answers.py --cards src/cards/card_005141.json --answer неизбежность
```

`--answer` можно повторять. Этот вариант применяется только к одному JSON,
чтобы одинаковое слово не отправлялось ко всем вопросам. В автономном режиме
карточки вне встроенных 935 ключей и явных гипотез отмечаются `not_checked`; наличие
полного каталога не означает, что ответы для всех карточек уже придуманы.

## Быстрый запуск

### Проверка нескольких возможных ответов

Пока нет машинного свидетельства, что ФИПИ принимает два разных по содержанию
ответа в одной карточке. Для `12BBAB` автор сообщила: «затем» принят,
«позже» отклонён. «Потом» пока только кандидат.

```bash
python3 src/check_fipi_answers.py --cards src/cards --alternatives-only --insecure
```

Отдельная очередь содержит **109 карточек**, максимум **419 POST-запросов**:
27 средств связи (№1), 9 паронимов (№5), 16 лексических исправлений (№6),
57 извлечений из текста (№25). Среди них 012CAB: «лакировочным», «лаковым»,
«лакировальным». Текущее оценивание приложения не считается доказательством
отклонения сервером: альтернативы нужно отправить на ФИПИ.

Все кандидаты проверяются, даже если первый принят. Сохранённый ключ также
отправляется для сравнения в том же запуске. Где ключ пока отсутствует,
проверяются все подготовленные гипотезы. Известный отказ «позже» для 12BBAB
не отправляется повторно. Отдельный файл плана скачивать не требуется.
Для продолжения повторить команду с `--resume ПУТЬ-К-РЕЗУЛЬТАТУ`.
Очередь пересекается с первыми двумя партиями намеренно: здесь нужна проверка
альтернатив после первого приёма. Исходные планы и их хеши не изменены.

В отчёте `withMultipleAcceptedStrings` считает карточки с несколькими принятыми
строками. Это повод для предметного анализа: слитная запись, пробелы, е/ё и
обратный порядок слов пары сами по себе не доказывают содержательную вариативность.
Признак множественных ответов можно установить после проверки разных по
содержанию строк для одного GUID и одного исходника. Грамматика, требуемая часть
речи и смысл отдельно проверяются редактором; список кандидатов не является
списком допустимых синонимов. Результаты не меняют production автоматически.

Полный план и основания: `dev/data/fipi_answer_variants.json`.
Инвентаризация позиций 1/5/6/25:
`dev/docs/content-audit/answer-variants-coverage.json`. Она явно различает
«подготовлена гипотеза» и «альтернатива пока не подготовлена»; ни одно из этих
состояний не является доказательством единственности ключа. Перечень не объявляется
исчерпывающим списком всех возможных русских синонимов.

Воспроизведение очереди разработчиком:

```bash
python3 dev/scripts/content/prepare_answer_variants.py --cards КАТАЛОГ-СЫРЫХ-JSON
python3 dev/scripts/bundle_fipi_checker.py
```

### Новая партия без повторной проверки старых ключей

Подготовлены **438 новых карточек**: соответствия (72), лексика (57),
НЕ (50), слитное написание двух слов (51), приставки (12), Н/НН (70),
запятые в сложноподчинённых предложениях (126). Это предположения,
а не новые подтверждённые ответы. У части карточек несколько кандидатов;
максимум 640 POST-запросов, до первого принятого ответа на карточку.

```bash
python3 src/check_fipi_answers.py --cards src/cards --new-only --insecure
```

Встроенные новые гипотезы доступны одним файлом скрипта. Отдельный JSON-план
скачивать не требуется. `--insecure` нужен только для режима TLS как у `curl -k`.
Режим `--new-only` не включает прежние 935 ключей и образец 005141. Поэтому
он не мешает текущей проверке первой партии; результаты сохраняются отдельно.
Для продолжения повторить все параметры и добавить `--resume ПУТЬ-К-РЕЗУЛЬТАТУ`.
Обычный режим прежнего плана сохраняется; обновление не меняет его хеш.

Гипотезы связаны с хешами сырой выгрузки 29.10.2026. Изменённый исходник
скрипт отклонит до отправки запроса. Для лексики и части соответствий использован
общий текст из прежней версии проекта: его нет в индивидуальном `qblock`.
Это происхождение контекста записано в `dev/data/fipi_new_hypotheses.json`;
новое совпадение общего текста не подтверждено. Перебор всех ответов не добавлялся.

После этой партии ещё **695** заданий с автоматической проверкой требуют
подготовки гипотез; 71 сочинение исключено из автоматической проверки.

### Исходный небольшой план

Начальный план содержит образец 005141 с гипотезой «неизбежность» и три
проверки вторых ответов. Для последних проверяются также текущие ключи:

```bash
python3 dev/scripts/check_fipi_answers.py
```

В конце будет напечатан путь к JSON в `dev/generated/`. Нужно прислать этот
файл, а не вручную переносить вывод терминала. Принятые варианты до импорта
не меняют рабочие ключи приложения.

По умолчанию **0,5 с между всеми запросами**, включая запросы текущих ключей,
и **ещё 10 с после каждых 20 запросов**. Настройки доступны явно:

```bash
python3 dev/scripts/check_fipi_answers.py --delay 0.5 --batch-size 20 --batch-delay 10
```

## Каталог любых исходников

Поддерживаются сырые JSON `{number, guid, html}` и текущий формат `data/`.
Имена файлов — `card_XXXXXX.json`. Если свежая выгрузка лежит в `src/cards`:

```bash
python3 dev/scripts/check_fipi_answers.py --cards src/cards
```

Для существующего банка проекта:

```bash
python3 dev/scripts/check_fipi_answers.py --cards data
```

Скрипт берёт имеющиеся ключи и явно подготовленные гипотезы, связывая их
с GUID и хешем именно переданного исходника. Если у свежего GUID имеется
старый ключ проекта, это кандидат для новой проверки, а не автоматическое
подтверждение новой редакции.

**Текущий охват:** все 2140 карточек учитываются в отчёте; кандидаты есть
у 936 (935 прежних ключей и 005141). Для остальных записывается явная причина
пропуска: 1133 требуют подготовки гипотез, 71 — сочинения. Это не готовые предположения для всех вопросов: после получения
полной свежей выгрузки нужно подготовить недостающие гипотезы. Сочинения
не проверяются таким методом. Список ID не заменяет тексты и формы заданий.

Скрипт не перебирает скрытно все комбинации. Можно добавить несколько
обоснованных кандидатов в [план](../data/answer_alternative_checks.json).
В режиме `find_accepted` проверка карточки прекращается после первого 3;
в `verify_alternatives` проверяются все явно перечисленные варианты, даже
если один уже принят. При технической ошибке остаток этой карточки остаётся
для повторного запуска, результат не выдаётся за отказ ФИПИ. После трёх технических ошибок подряд
запуск останавливается с сохранением результата; его можно продолжить.

## Продолжение после остановки

Результат атомарно сохраняется после каждого ответа. Если запуск остановлен,
используется напечатанный ранее путь:

```bash
python3 dev/scripts/check_fipi_answers.py --resume dev/generated/ИМЯ-ФАЙЛА.json
```

Для каталога исходников при продолжении нужно повторить `--cards`:

```bash
python3 dev/scripts/check_fipi_answers.py --cards src/cards --resume dev/generated/ИМЯ-ФАЙЛА.json
```

Принятые и отклонённые ответы не отправляются повторно. Технические ошибки
повторяются; паузы можно изменить. Смешать результаты другого плана, изменённых
исходников или другого сервера нельзя. При новом запуске существующий файл
не перезаписывается, для продолжения есть `--resume`.

## Если curl работает, а Python сообщает ошибку соединения

`curl -k` отключает проверку TLS-сертификата; по умолчанию Python её выполняет.
Для запуска с тем же поведением, что у предоставленного автором `curl -ks`:

```bash
python3 src/check_fipi_answers.py --cards src/cards --insecure
```

Это явный режим без проверки сертификата; автоматического переключения на него
нет. Если используется прокси с собственным сертификатом, можно сохранить
проверку TLS через `--ca-file proxy-ca.pem`. Текст ошибки сессии и запросов
теперь выводится в терминал; HTTP-ошибка отделена от ошибки соединения.
Параметры TLS сохраняются в журнале каждого запуска. При медленном ответе
можно дополнительно задать `--timeout 60`.

## Значения ответа сервера

- `3` при успешном HTTP-запросе — `accepted`;
- `2` — `rejected`;
- другой текст, HTTP 403/500, таймаут — отдельная техническая ошибка;
- отсутствие гипотезы — `not_checked`, не отказ и не неправильный ответ.

Для выбора вариантов готовится битмаска по реальной форме. Сопоставление
и номера предложений сохраняют порядок; числовая строка не превращается
автоматически в битмаску только из-за наличия цифр. Поле `answer` в плане
человекочитаемо, `wireAnswer` — фактически отправляемая строка.

Журнал содержит GUID, хеш исходника, время, отправленный ответ, HTTP-статус
и ответ сервера. Сессионные cookies хранятся только в памяти. Сырой HTML
не исполняется. Проверка не скачивает заново и не сравнивает текст задания:
это явно отмечено `liveTextCompared=false`; исходники берутся из выгрузки.

**Подсчёт:** не считать вхождения слова `accepted` поиском по JSON. У карточки
есть общий `status`, а у каждой попытки внутри `attempts` — собственный
`status`: принятие одной попытки записывается в обоих местах. Сводка
`summary.withAcceptedAnswer` считает карточки один раз; `summary.notChecked`
показывает число карточек без отправленного ответа. В конце запуска эти числа
также печатаются в терминал. При остановке часть ещё не обработанных карточек
может не попасть в `results`, поэтому для общего числа используется `cardsInPlan`.

Проверены локально: HTTP-протокол и cookie-сессия, кодирование, ошибки вместо
ложного отказа/приёма, обе паузы, сохранение и продолжение без повторов.
Новая реальная серверная проверка из облачной среды невозможна из-за 403
прокси; запуск автора даст необходимое подтверждение.
