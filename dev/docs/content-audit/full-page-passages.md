## Почему привязка надёжна

Общий текст — отдельный `div.qblock` без ID, с инструкцией «Прочитайте текст…».
После него идут задания. Для каждой карточки отдельно проверяются её шестизначный
код, GUID в форме, код группы из `number-in-group` и порядковый номер внутри
группы. В группе один и тот же код; номера идут от 1 без пропусков или повторов.
Следующий самостоятельный вопрос закрывает текущую группу, новый текст открывает
следующую. Положение на странице служит только для нахождения блока; одного
соседства недостаточно. Все 2140 кодов/GUID сверены, чужие тексты не подбираются
по сходству фраз. Учтены дополнительные CSS-классы `qblock1` у сочинений.

Пять прежних согласований выделений теперь подтверждены самим HTML:
`082CB8`, `2BA3EC`, `9273A5`, `E96B4A`, `F5E433`. В E96B4A сохранена точная
граница выделения источника: подчёркнуто «ход», окончание «ом» остаётся вне него.

## Нерешённые предметные вопросы

В `6E2A0F` новый источник подтверждает прежний общий текст (группа `03EEC3`).
ФИПИ принял `3133`; причина исключения предложения 26 не объясняется подменой
текста в проекте. Не утверждается, что иной кандидат `263133` отклонён:
такого результата проверки нет. Объяснение не подгоняется под ключ.

Для `88BC90` источник также подтверждает прежний текст (группа `A26773`):
«почти весь» в тексте и «всех произведений» в варианте остаются предметной
неоднозначностью при принятом ключе `234`.

Это не новое предметное ревью ответов или объяснений. Оригинальные журналы
ФИПИ и планы проверки остаются неизменными, включая хеши прежней разметки.
Старые версии общих текстов сохранены в новом журнале. Редакторские привязки
получили новые хеши с указанием источника и без повторного предметного ревью.
По действующей политике смена поля `text` меняет `materialVersion`; история
попыток не удаляется, миграция результатов не выполнялась.

## Повторение

```bash
python3 dev/scripts/audit_fipi_passages.py --check
# Для исходной копии проекта, с логом и обновлением редакторских хешей:
python3 dev/scripts/audit_fipi_passages.py --apply
python3 dev/scripts/publish_content.py
bash scripts/install.sh
```

Для подготовки нужен `lxml` из `dev/requirements.txt`; production работает
без `dev/`. `--check` ничего не меняет. Автоматическое применение допускает
только совпадающее содержание с отличающейся разметкой. Иные тексты, неверный GUID,
несогласованная группа или кодировка останавливают импорт.
